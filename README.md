# Hotline Camp — Сочи 2026

Лендинг триатлонного кэмпа Hotline в Сириусе, 27 сентября — 4 октября 2026 года.
Кэмп завершён; на странице сохранены программа и материалы о тренерах.

## Что внутри

- программа и ритм предстартовой недели;
- текущая погода в Сочи, температура моря, восход и закат из Open-Meteo;
- тренеры Евгений Тихонин и Максим Кубышко;
- палитра и автоматическая тема по солнечному циклу Сочи;
- просмотр палитры в течение суток, влияние UV на насыщенность и ветра на графическое поле;
- сохраняемые ручные настройки темы и движения в меню;
- четыре одинаковых нативных `<button type="button" disabled>` с текстом
  «Приём заявок закрыт», без ссылки на форму;
- чистая статическая публикация через GitHub Pages.

## Календарное состояние

Счётчики на первом экране и в меню, заголовок и пояснение финального блока
используют одно состояние, вычисленное по календарному дню в `Europe/Moscow`:
до 27 сентября — ожидание, 27 сентября — 4 октября включительно — дни кэмпа,
с 5 октября — «8 дней вместе» и «Кэмп завершён». Состояние обновляется в полночь
Сочи и при возврате на страницу. Даты заданы в календарном блоке `public/app.js`.

HTML без JavaScript и описания для поиска и соцсетей уже сообщают о завершении
кэмпа. Закрытая регистрация не открывается автоматически при смене даты.
Следующий кэмп или возобновление записи требуют новых подтверждённых данных.

## Погода и оформление

Weather API запрашивает текущие условия и восход/закат на один день; Marine API —
температуру моря. Air Quality API даёт текущий и почасовой UV. Каждый источник
может завершиться отдельно: частичная ошибка не скрывает доступные показатели.
Загрузка и отсутствие данных обозначаются текстом. Наблюдения обновляются раз
в 30 минут, в том числе при возврате на вкладку; запрос ограничен 12 секундами.

Прогноз на даты кэмпа скрыт и не запрашивает дальний горизонт. Его оставшаяся
реализация сохранена согласно прежнему решению; проверки защищают отсутствие
ячейки и лишнего запроса, а не требуют наличия этого кода.

Солнечный режим использует достоверные восход и закат текущего дня; до их
получения применяется системная тема. Ручной выбор светлой или тёмной темы
имеет приоритет. В просмотре суток UV подписан как прогноз. «К текущему времени»
сбрасывает выбранный час, сохраняя раскрытую панель; сворачивание завершает
просмотр. Отсутствующие или устаревшие ветер и UV не подменяются нулём и не
управляют оформлением. Насыщенность от UV меняется при поддержке CSS relative
colors. Влажность и осадки влияют только на ограниченное размытие фотографии
первого экрана; текст остаётся чётким.

WebGL-поле приостанавливается вне экрана и в скрытой вкладке; фавиконка —
в скрытой вкладке. Режим без движения оставляет статичный кадр.
Фотографии используют `srcset` без изменения утверждённых кадров. Оригиналы
сохранены; копии шириной 480 и 960 px воспроизводятся командой
`sh scripts/prepare_images.sh` на macOS (системный `sips`, без сборки сайта).

## Локальная разработка и проверки

Сборка, Node.js и пакетный менеджер не нужны. Исходник сайта находится в `public/`.

```bash
python3 -m http.server 3000
```

Сайт: `http://localhost:3000/public/`.
Браузерные сценарии: `http://localhost:3000/scripts/check_browser.html`.
При открытии тестовой страницы сценарии запускаются автоматически, результат
появляется над сайтом; подробности раскрываются в «Результатах сценариев».

Проверяется настоящий HTML и `app.js`: границы календарных дней в Сочи,
согласованность финала со счётчиками, закрытые CTA, солнечная и ручные темы,
просмотр и возврат к текущему времени, изоляция меню и возврат фокуса,
загрузка, частичный и полный сбой погоды, свежесть ветра/UV. Время фиксировано,
все три API подменены, хранилище настроек изолировано, аналитика удалена,
внешние запросы запрещены CSP. Вымышленные данные остаются в `scripts/` и не
публикуются. Результат не зависит от настоящей погоды и настроек пользователя.

Это проверки поведения DOM; они не заменяют реальную клавиатуру, физический
телефон, экранный диктор или визуальную оценку. Затронутый текст проверяем
реальным рендером. Неизменённые состояния повторно не аудируем.

```bash
python3 scripts/check_static.py
git diff --check
```

Статическая проверка защищает закрытое состояние всех CTA, завершённый HTML
без JavaScript, четыре видимые погодные ячейки, утверждённые фотографии,
семантику и статическую архитектуру. Она не требует старую ссылку на форму
в документации и не доказывает корректность динамической логики.

## Публикация и договорённости

Основной адрес: [hotlinecamp.ru](https://hotlinecamp.ru/). Canonical и Open Graph
указывают на этот домен. Контакт организатора — Елена Родионова,
`@elenarodionova_happy`; контакт не заменяет закрытую регистрацию.

Обязательные правила — `AGENTS.md` и `docs/interface-rules.md`.
Публикация выполняется по прямому разрешению пользователя.
Workflow `.github/workflows/pages.yml` запускает `scripts/check_static.py` и
публикует только папку `public/` через GitHub Pages Actions без шага сборки.
Браузерные сценарии запускаются локально при изменении соответствующей логики;
в текущий CI они не входят.
